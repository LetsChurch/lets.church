# Anthropic discounted processing for the annotation fallback

_Checked 2026-08-28 against Anthropic's first-party Claude Platform documentation and API reference._

## Decision

**No. Anthropic does not offer a request-level synchronous discounted tier analogous to OpenAI Flex at Batch pricing.** On the synchronous `POST /v1/messages` endpoint, the request field `service_tier` accepts only `"auto"` and `"standard_only"`; it does not accept `"batch"`. Anthropic documents Batch as a separate, asynchronous service reached through `POST /v1/messages/batches`. [Messages API reference](https://platform.claude.com/docs/en/api/messages/create) · [Service tiers](https://platform.claude.com/docs/en/api/service-tiers) · [Message Batches create reference](https://platform.claude.com/docs/en/api/messages/batches/create)

The closest discounted alternative is the **Message Batches API**, which charges **50% of standard input and output token prices**. It cannot replace the existing live OpenRouter content-filter fallback without changing that fallback into a durable asynchronous workflow: batch creation returns a batch resource rather than the model result, the documented completion workflow retrieves/polls `GET /v1/messages/batches/{message_batch_id}`, and `results_url` exists only after processing ends. [Batch processing: operation and pricing](https://platform.claude.com/docs/en/build-with-claude/batch-processing) · [Retrieve a Message Batch](https://platform.claude.com/docs/en/api/messages/batches/retrieve)

**For a no-poll live fallback, the available Anthropic path is a normal `POST /v1/messages` request at standard pricing.** Prompt caching may reduce the price of repeated input prefixes, but it is not a generally discounted processing tier and does not discount generated output. [Pricing: model pricing and prompt caching](https://platform.claude.com/docs/en/about-claude/pricing)

## Polling and failure semantics

A Message Batch starts processing immediately after creation but may take up to 24 hours. The status endpoint is explicitly documented as idempotent and usable to poll for completion. Its `processing_status` progresses through `in_progress`, optionally `canceling`, and `ended`; `results_url` is null until processing ends. Individual requests can finish as succeeded, errored, canceled, or expired, and JSONL result order is not guaranteed, so callers must correlate by `custom_id`. [Create a Message Batch](https://platform.claude.com/docs/en/api/messages/batches/create) · [Retrieve a Message Batch](https://platform.claude.com/docs/en/api/messages/batches/retrieve)

Batch capacity is separate from normal Messages capacity: Anthropic applies its own Batch API endpoint RPM and processing-queue limits, shared across models. Those limits are maxima rather than guaranteed throughput, and Anthropic warns that demand or request volume can slow processing and increase 24-hour expirations. [Rate limits: Message Batches API](https://platform.claude.com/docs/en/api/rate-limits#message-batches-api) · [Batch limitations](https://platform.claude.com/docs/en/build-with-claude/batch-processing#batch-limitations)

For synchronous Standard traffic, HTTP 529 means the API is temporarily overloaded. HTTP 429 covers rate limits, acceleration limits after a sharp traffic increase, and certain spend-cap conditions. Anthropic's official SDKs retry transient connection, rate-limit, and 5xx failures twice by default with exponential backoff, but retry behavior does not turn Standard into reserved or discounted capacity. [Claude API errors](https://platform.claude.com/docs/en/api/errors#http-errors)

## Recommendation

Keep the content-filter fallback live through OpenRouter, or replace it with direct Anthropic `POST /v1/messages` at standard pricing if eliminating OpenRouter is more important than preserving the discount. Do **not** substitute Message Batches unless the annotation pipeline can durably enqueue work, persist the batch/request IDs, poll or revisit completion later, retrieve JSONL results, and tolerate up to the 24-hour batch window.

If the fallback is made asynchronous, Message Batches is the exact closest public Anthropic alternative: it supplies the same 50% input/output discount target, but the discount is inseparable from asynchronous batch semantics. [Batch processing](https://platform.claude.com/docs/en/build-with-claude/batch-processing)
